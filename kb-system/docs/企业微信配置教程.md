# 企业微信配置教程（面向管理员）

> 这份教程写给**非技术出身的管理员**。只要照着一步一步做，大约 30 分钟就能让"团队知识库机器人"在企业微信里跑起来。
> 遇到问题时先翻到最后的「常见问题排错」。

---

## 第 0 步：准备（你需要先有这些东西）

| 需要的东西 | 说明 | 没有怎么办 |
|---|---|---|
| 一台能 24 小时开机的服务器 | 公司内网服务器或云服务器（1 核 1G 就够） | 找 IT 同事申请 |
| 一个域名 | 比如 `kb.example.com`，解析到这台服务器 | 找 IT / 域名管理员 |
| HTTPS 证书 | 企业微信**要求回调地址必须是 HTTPS** | 用 Let's Encrypt 免费证书，或找 IT 要 |
| 企业微信管理后台权限 | 你需要是企业微信的「管理员」 | 找公司的企业微信超级管理员授权 |
| 服务器上装好 Node.js | 版本 **≥ 22.19**（`node -v` 查看） | 到 nodejs.org 下载 LTS 版 |

---

## 第 1 步：启动知识库服务

把项目代码放到服务器上（比如 `/opt/kb-system`），然后**先启动两个服务**，再去做企业微信后台的配置。顺序很重要——因为企业微信在你保存回调配置的那一刻，会立刻来访问你的服务做验证，服务没启动就会验证失败。

```bash
# 1. 启动知识库内核（端口 5181）
cd /opt/kb-system
TEAM_PORT=5181 node ../shared-knowledge/team-app/src/server.mjs &

# 2. 配置采集服务的环境变量
cd /opt/kb-system
cp .env.example .env
# 编辑 .env，先只填这三项以外的可以先不动：
#   KB_URL=http://127.0.0.1:5181
#   COLLECTOR_PORT=9100
# 企业微信的三个值（WECOM_TOKEN 等）下一步拿到后再填

# 3. 启动采集服务（端口 9100）
cd collector
set -a; . ../.env; set +a
npm start &
```

> 正式运行建议用 pm2 托管（见项目 README 的「pm2 部署」一节），上面这种 `&` 方式只适合第一次调试。

确认服务起来了：

```bash
curl http://127.0.0.1:9100/wecom/callback
# 返回 403 signature mismatch 或 404 之外的内容都说明进程活着（没带参数访问属正常报错）
```

## 第 2 步：在企业微信后台创建自建应用

1. 用管理员身份登录 **企业微信管理后台**：https://work.weixin.qq.com/wework_admin
2. 顶部菜单点 **「应用管理」** → 往下找到 **「自建」** 区块 → 点 **「创建应用」**。
3. 填应用信息：
   - 应用名称：随便起，比如 `知识库小助手`
   - 应用 Logo：随便传一张
   - 可见范围：选择允许使用机器人的成员/部门（先选你自己测试，跑通后再扩大）
4. 创建完成后点进这个应用，记下三样东西（后面要填进 `.env`）：

| 后台页面上的名字 | 填到 .env 的哪一项 | 长什么样 |
|---|---|---|
| **AgentId** | `WECOM_AGENT_ID` | 一串数字，如 `1000002` |
| **Secret**（点「查看」会发到你的企业微信） | `WECOM_SECRET` | 一串字母数字 |
| **企业 ID**（在「我的企业」页面最底部） | `WECOM_CORP_ID` | `ww` 开头的一串 |

---

## 第 3 步：配置「接收消息」回调（关键一步）

1. 在你刚创建的应用详情页，找到 **「接收消息」** 区块，点 **「设置 API 接收」**。
2. 页面上要填三项：
   - **URL**：`https://你的域名/wecom/callback`（必须 HTTPS，必须能通过 nginx 转发到服务器的 9100 端口，见第 6 步）
   - **Token**：自己编一串，比如 `kb-2026-token`，**同时**填进 `.env` 的 `WECOM_TOKEN`
   - **EncodingAESKey**：点「随机获取」生成 43 位字符串，**同时**填进 `.env` 的 `WECOM_ENCODING_AES_KEY`
3. **先别急着点保存！** 先做两件事：
   - 确认 `.env` 里 `WECOM_TOKEN`、`WECOM_ENCODING_AES_KEY`、`WECOM_CORP_ID` 已填好
   - **重启采集服务**，让新配置生效
4. 现在点 **「保存」**。
   - 企业微信会立刻向你的 URL 发一个验证请求。
   - 看到「保存成功」= 验证通过 ✅
   - 看到「验证失败」= 翻到「常见问题排错」第 1 条。

---

## 第 4 步：配置企业可信 IP（否则机器人无法主动发消息）

提问的答案是通过「应用消息」主动推给员工的，企业微信要求消息发送方的服务器 IP 在可信名单里：

1. 应用详情页 → 找到 **「企业可信 IP」** → 点「配置」。
2. 填入你服务器的**出口公网 IP**（在服务器上执行 `curl ifconfig.me` 可以看到）。
3. 保存。

> 不配这一步也能收录消息，但员工提问后收不到答案推送。

---

## 第 5 步：成员怎么用

把机器人应用的可见范围放开给团队成员后，大家在企业微信里找到「知识库小助手」这个应用，直接私聊它即可：

| 成员的操作 | 机器人的反应 |
|---|---|
| 随便发一段文字（会议纪要、客户反馈、链接摘要……） | 收录进知识库，回执「已收录 #xxxxxxxx ✅」 |
| 发 `帮助` | 回复使用说明 |
| 发 `问： xxx`（以"问："开头） | 先回「收到问题，正在查知识库…」，稍后把答案推送过来 |
| 发语音 | 自动转文字后按文本处理（需在应用里开启语音转文字） |
| 发图片 | 先存图片链接占位（OCR 识别即将上线） |
| 发 `撤回 #编号` | 机器人会指引你联系管理员操作（撤回是管理员权限） |

转发收藏：看到群里有价值的消息，长按 → 转发 → 选「知识库小助手」，同样会入库。

## 第 6 步：nginx 配置示例（HTTPS 反向代理）

企业微信只认 HTTPS，所以前面要架一层 nginx。下面是一份最小可用配置（假设域名 `kb.example.com`，证书已签好）：

```nginx
server {
    listen 443 ssl;
    server_name kb.example.com;

    ssl_certificate     /etc/letsencrypt/live/kb.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/kb.example.com/privkey.pem;

    # 企业微信回调 → 采集服务
    location /wecom/callback {
        proxy_pass http://127.0.0.1:9100;
        proxy_set_header Host $host;
        proxy_read_timeout 10s;   # 企微被动回复有 5 秒时限，超时别设太长
    }
}

# HTTP 强制跳转 HTTPS
server {
    listen 80;
    server_name kb.example.com;
    return 301 https://$host$request_uri;
}
```

改完执行 `nginx -t` 检查语法，然后 `systemctl reload nginx`。

## 第 7 步：定时任务（cron）示例

知识库的"每日摘要、Wiki 编译、每周巡检"由定时任务触发（具体脚本见 `librarian/`）。编辑 crontab：

```bash
crontab -e
```

加入下面三行（分钟特意避开整点和半点，减少拥堵）：

```cron
# 每日摘要：每天 8:10 生成并推送到企业微信
10 8 * * *  cd /opt/kb-system && node librarian/scripts/digest.mjs >> /var/log/kb-digest.log 2>&1

# Wiki 编译：每 4 小时跑一次
17 */4 * * * cd /opt/kb-system && node librarian/scripts/compile.mjs >> /var/log/kb-compile.log 2>&1

# 每周巡检：每周一 9:10
12 9 * * 1  cd /opt/kb-system && node librarian/scripts/lint.mjs >> /var/log/kb-lint.log 2>&1
```

## 常见问题排错

### 1. 保存回调配置时提示「验证失败」

按顺序排查：

1. **服务启动了吗？** 在服务器上 `curl http://127.0.0.1:9100/wecom/callback`，没反应说明采集服务没起。
2. **顺序对了吗？** 必须先填好 `.env` 里的 Token / EncodingAESKey 并**重启采集服务**，再点后台「保存」。改过 `.env` 没重启是最常见的错误。
3. **Token 一致吗？** 后台填的 Token 必须和 `.env` 里 `WECOM_TOKEN` **一字不差**（大小写敏感）。
4. **EncodingAESKey 一致吗？** 必须是后台「随机获取」的那 43 位，不能自己编。
5. **nginx 通吗？** 在服务器上 `curl https://你的域名/wecom/callback`，如果超时或 502，是 nginx / 防火墙 / 域名解析的问题，和知识库无关。
6. **看日志**：采集服务日志里出现 `[GET] URL 验证通过` 说明请求到达了服务；完全没日志说明请求根本没进来（查 nginx）。

### 2. 发消息有回执，但提问后收不到答案

- 答案是通过应用消息**主动推送**的，检查第 4 步「企业可信 IP」是否配置。
- 检查 `.env` 里 `WECOM_SECRET` / `WECOM_AGENT_ID` 是否填对。
- 看采集服务日志里 `[answer]` 开头的行有没有报错。

### 3. 发消息完全没有回执

- 企微被动回复有 5 秒时限，知识库内核（5181 端口）如果没启动，入库会超时失败——但此时你仍应收到「success」空回执（表现为没有回执消息）。先确认内核在跑：`curl http://127.0.0.1:5181/api/records`。
- 确认回调走的是 POST 到了服务：日志里应有 `[POST]` 相关行。

### 4. 同一条消息被收录了两次

正常不会：每条消息用企微 `MsgId` 做幂等键，重复推送会被内核去重。如果发现重复，检查是不是自己用模拟器拿同一个 MsgId 重复发了。

### 5. 想换一个大模型（LLM）

编辑 `.env` 里的三项（任何 OpenAI 兼容协议的服务都可以，比如 Kimi、DeepSeek、公司内部网关）：

```
KB_LLM_BASE_URL=https://api.moonshot.cn/v1
KB_LLM_API_KEY=sk-你的key
KB_LLM_MODEL=kimi-k2
```

重启相关服务即可。**不配置 LLM 也能用**：提问会降级为直接返回检索到的证据列表，不会报错。

### 6. 回调地址想换路径 / 端口

路径 `/wecom/callback` 写在采集服务里，换路径要改代码（`collector/src/server.mjs`）；换端口只需改 `.env` 的 `COLLECTOR_PORT` 和 nginx 的 `proxy_pass`，重启即可。
