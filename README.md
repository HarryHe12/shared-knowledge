# 公司内部知识服务

微信、电脑 Agent 与未来内部小程序共用一个知识服务。网页用于账号审批、公司/品牌/门店配置和接入管理。第一阶段适合一家公司的 12 家门店试点。

## 功能

- 受信内部小程序可在管理员限定的品牌/门店范围内，以现有员工身份建立独立、仅入口可用的知识身份。每次登录同步当前门店范围并撤销旧会话；不共用旧负责人，不开放密码或设备登录，不继承公司公共/管理资料。新增身份结构需先显式迁移，默认关闭，配置见服务说明。

- 公司 → 品牌 → 门店组织结构，店员、店长、品牌负责人、公司负责人的权限实时生效，多家公司逻辑隔离。
- `/organization` 管理页支持批量建店、岗位授权、知识范围和员工外部身份绑定。
- `/join` 员工凭邀请链接自填资料和申请岗位；`/approvals` 本店店长审核店员、本品牌负责人审核店长、公司负责人审核品牌负责人，通过后自动分配公司与岗位权限。
- `/api/v1` 统一聊天、来源引用、跨授权范围查询、记录生命周期；保存按内容和岗位自动推导落点范围，回复“换到 XX”可改存；SDK 提供未来小程序的 `wx.request` 适配。
- 企业微信验签后持久入队，以真实员工身份处理；断线重试去重，禁止应用密钥冒充员工。
- 所有入口仅供内部员工，品牌或门店接入上限与员工权限取交集；旧平面 Wiki/静态摘要默认停用。

- 注册与登录独立切换，提供审批步骤、填写提示和移动端布局。

- 自主注册、逐级审核、按知识范围授予只读/可提交权限，支持账号停用、设备撤销与审计；邀请和申请本身不赋予资料访问权。
- macOS 与 Windows 客户端通过设备码连接，凭证自动保存在系统钥匙串或 Windows 凭据管理器。

- 保存原始工作记录，支持幂等写入、版本纠错、撤回恢复及彻底删除。
- 提取事项草稿，经用户确认后保存。
- 提供混合检索、精确引用展开和状态证据，由调用方 Agent 补查、澄清并回答。
- 读取记录、事项、状态历史并总结。

## 使用

需要 Node >=22.19 与 npm。运行 `npm ci`，再运行 `npm run dev`。

在 AI 宿主中加载 [Skill 入口](team-app/skill/SKILL.md)。默认只监听 127.0.0.1:5181，正式模式必须登录；首次运行先初始化管理员，步骤见服务说明。
客户端位于 [knowledge.mjs](team-app/scripts/knowledge.mjs)，数据库默认在 `team-app/.data/team.sqlite`。配置、模型凭证与权限边界见 [服务说明](team-app/README.md)。

## 开发

运行 `npm test` 或 `npm run quality-and-tests`，覆盖内核、SDK、HTTP、采集队列和旧导出隔离。

架构、12 家门店落地步骤、API、未来小程序接入和仍待完成的能力见 [服务说明](team-app/README.md)；企业微信配置见 [采集服务说明](kb-system/README.md)。
继续开发或交给其他 Agent 时，先读 [Kimi 接手说明](KIMI_HANDOFF.md)，其中区分已实现功能、试点部署状态和仍待真实验收的部分。
维护 team-app 后端、客户端、Skill，以及账号/管理页面；已有外部知识文件与本地数据库保留。
